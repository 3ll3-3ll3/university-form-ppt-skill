# 大学信息查询 + PPT 模板填写 + Google Drive 归档 Skill

[English](README.md) | [简体中文](README.zh-CN.md)

这是一个固定工作流 Skill。用户只要提供大学中文名、英文名、学校邮箱/域名、学院名或其他明显学校线索，就直接执行完整流程，不再询问是否继续。

核心能力：

- 自动识别学校；
- 核验官方中文名、学校官方英文全名、代表性校区、地址、邮编和经纬度；
- 随机生成较短的中文姓名拼音和适配版面的数字 Student ID；
- 只替换最新用户确认 PPT 模板中的 `{{name}}`、`{{student_id}}`、`{{school_name}}`；
- 严格保护原模板格式和所有非占位符内容；
- 实际渲染 PPT 为 PNG 并进行视觉验收；
- 每次生成后自动把 MD/PPTX/PNG 三件套归档到 Google Drive；
- 将 Google Drive 上传成功 + 文件夹回读确认设为强制完成条件。

## 仓库角色

GitHub 只保存可复用工作流：

- `SKILL.md`：唯一正式执行规范；
- `AGENTS.md`：关键不变量；
- `assets/certificate_template.pptx`：用户最后一次明确指定的最新模板；
- `scripts/`：姓名/学号、PPT、归档辅助脚本；
- `docs/`：学校查询、输出、PPT、归档与维护规则；
- `tests/`：回归测试。

**具体学校每次生成的 MD/PPTX/PNG 不保存到 GitHub，只保存到 Google Drive。**

## 学校信息核验

来源优先级：

1. 学校官方网站；
2. 官方招生网站；
3. 官方国际交流网站；
4. 官方联系方式/信息公开页面；
5. 在校区和地址已核实后，再使用可靠地图/地理数据库确认坐标。

必须使用学校自己公开采用的官方英文全名，禁止自行翻译、缩写或为了排版使用简称。正文和右下角落款的学校英文名必须完全一致。

若学校有多个校区，经纬度不要全部输出，只选最多两个最主要、最常见、最有代表性的校区，并明确标注校区名。

## 随机姓名与 Student ID

项目字段约定：

- `First name` = 姓的拼音；
- `Last name` = 名的拼音；
- PPT 姓名 = `姓拼音 名拼音`。

优先选择较短的二字或三字中文姓名，不根据邮箱用户名推测真实姓名。

Student ID 每次重新随机生成纯数字，长度由版面决定，通常优先 7–8 位，不默认附加固定前缀。若第一行换行：先换更短姓名，再换更短 Student ID，再重新渲染检查。

## PPT 硬性规则

当前模板约定：

- `{{name}}` 1 处；
- `{{student_id}}` 1 处；
- `{{school_name}}` 2 处。

只允许替换这三类占位符。优先直接修改 PPTX 内部 XML，不重建文本框。

禁止为了第一行适配修改正文：

- 字体；
- 字号；
- 颜色；
- 行距/段距；
- 正文文本框大小和位置；
- 正文位置。

同时保护页面尺寸、背景、图形、日期、学院/系、专业和其他所有非占位符内容。

第一行姓名 + Student ID 必须完整单行。第二行及之后允许自然换行，但禁止人为插入硬换行或硬拆词。

右下角必须使用官方英文全名并始终单行；确实放不下时，只允许对右下角学校名这一处做最小必要的宽度、位置、字间距或极小字号调整，不能改正文和整体版式。

如果源模板含 `SAMPLE / NOT VALID` 或 `仅供演示，不具效力`，必须永久保留且可见；新模板本身若不含这些标识，不得假定它一定存在。

每次生成后必须把实际 PPT 渲染为 PNG，肉眼检查第一行、正文自然顺排、正文/落款官方英文全名、落款单行、非占位符无误改、整体格式正常，以及源模板中原有的演示标识是否保留。失败必须重做再交付。

## 聊天交付顺序

1. 实际 PPT 渲染 PNG；
2. PPTX；
3. 学校中文名；
4. Official English Name；
5. First name；
6. Last name；
7. Student ID；
8. Address；
9. City；
10. State/Province；
11. Postal/Zip code；
12. 经纬度最后。

每个学校/表单字段单独放在可复制代码块中。默认不输出 Country/Region、Address line 2、VAT/GST ID。

## Google Drive 自动归档

每次生成必须自动归档到：

```text
大学PPT生成记录/<中文学校名>/
```

每次保存同名三件套：

```text
YYYY-MM-DD_HH-mm.md
YYYY-MM-DD_HH-mm.pptx
YYYY-MM-DD_HH-mm.png
```

时间戳使用本地生成时间，精确到 1 分钟。同一学校同一分钟再次生成时，仅为防止覆盖追加 `_<student_id>`。

MD 至少记录：中文校名、官方英文全名、用户原始输入、First name、Last name、完整随机姓名、Student ID、Address、City、State/Province、Postal/Zip code、校区、经纬度、PPT 验收结果，以及 PPT/PNG 的**真实 Google Drive 链接**。

### 强制完成条件

Google Drive 归档必须且自动完成，不允许等待用户第二次说“请完成/归档”。一次生成只有在以下步骤全部成功后才算完整完成：

1. 最终 PPTX 上传成功；
2. 最终真实渲染 PNG 上传成功；
3. 写入真实 PPT/PNG Drive 链接后的 MD 上传成功；
4. 回读目标学校文件夹，确认预期 MD/PPTX/PNG 三件套确实存在。

任何外部动作失败必须明确写：`该步骤当前没有成功完成。`，禁止伪造上传、渲染、链接、GitHub 更新、Commit 或回读成功。

## REDO

只要英文校名、简称、第一行换行、正文格式、右下角落款、模板版本或 Drive 文件有误，都必须全链路 REDO：重新生成 PPT → 渲染 PNG → 视觉验收 → 替换/更新 Drive PPTX → 替换/更新 Drive PNG → 更新 Drive MD → 回读确认。

## 规则同步

用户说“以后增加规则 / 修改规则 / 记住以后”等永久工作流变化时，必须同步更新 `SKILL.md`、相关中英文文档、相关脚本、相关测试，以及用户明确更换的最新模板。只有 GitHub 实际写入成功才能声称同步完成。
