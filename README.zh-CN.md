# 大学信息填写 + PPT 替换 Skill

[English](README.md) | [简体中文](README.zh-CN.md)

这是一个固定工作流 Skill：识别学校、核验官方信息、生成随机姓名和学号、仅替换 PPT 模板中的 `{{name}}`、`{{student_id}}`、`{{school_name}}`，实际渲染 PNG 进行视觉验收，并在每次成功生成后自动归档到 Google Drive。

## 仓库角色

GitHub 仓库只保存工作流本身：

- `SKILL.md`：唯一正式执行规范；
- `assets/certificate_template.pptx`：用户最后一次明确指定的最新模板；
- `scripts/`：姓名、学号、PPT、归档辅助脚本；
- `docs/`：中英文规则；
- `tests/`：工作流测试。

**具体学校生成记录不再保存到 GitHub。**

## Google Drive 归档

每次生成都必须自动保存到：

```text
大学PPT生成记录/<中文学校名>/
```

每次生成保存同名三件套：

```text
YYYY-MM-DD_HH-mm.md
YYYY-MM-DD_HH-mm.pptx
YYYY-MM-DD_HH-mm.png
```

时间戳使用本地生成时间，精确到 1 分钟。如果同一学校在同一分钟生成第二条记录，仅为避免冲突追加 `_<student_id>`。

PNG 必须由实际 PPT 直接渲染。MD 必须记录学校信息、随机姓名、Student ID、地址、校区、经纬度、PPT 验收结果，并写入已经真实上传成功的 PPT/PNG Google Drive 链接。

### 强制完成条件

Google Drive 归档是**必须且自动完成**的硬性步骤，不允许等待用户再次说“完成归档”。

一次生成只有同时满足以下条件才算完整完成：

1. PPTX 上传成功；
2. 实际渲染 PNG 上传成功；
3. MD 上传成功；
4. 再次读取目标 Drive 文件夹，确认三件套确实存在。

任何一步失败，都必须明确写：`该步骤当前没有成功完成。`，并且禁止声称本次生成已完整完成。

## PPT 硬性规则

- 学校名必须使用官方英文全名，不能为排版改成简称。
- 第一行姓名和 Student ID 必须保持一行；优先换短姓名，再换短学号，禁止改正文排版。
- 后续正文只能自然换行，不得人为插入换行。
- 右下角官方英文全名必须单行；必要时只允许该处做最小局部适配。
- `SAMPLE / NOT VALID` 和 `仅供演示，不具效力` 必须永久保留。

## 聊天交付顺序

先给真实 PPT 渲染 PNG，再给 PPTX，再依次给学校字段，最后经纬度。Google Drive 归档在同一次工作流中自动执行并验收，不应由用户二次触发。

## 规则同步

用户修改工作流规则后，必须同步更新 `SKILL.md`、相关中英文文档、相关脚本和测试。只有 GitHub 实际写入成功后才能声称同步完成。
