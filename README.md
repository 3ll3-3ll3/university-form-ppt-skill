# University Form + PPT Skill

[English](README.md) | [简体中文](README.zh-CN.md)

A Codex/ChatGPT skill for a narrow workflow:

- identify a university from a school name, email address, or domain;
- verify the official Chinese name, official English full name, campus address, postal code, and coordinates;
- generate a short random Chinese-pinyin student name and layout-friendly numeric student ID;
- replace only `{{name}}`, `{{student_id}}`, and `{{school_name}}` in the user-approved PPT template;
- preserve the template formatting and permanent demo/non-valid markings;
- render-check the first line, natural body flow, and bottom-right single-line official school name before delivery;
- automatically archive every completed generation to Google Drive as Markdown + PPTX + the PNG rendered from that PPT.

## Repository purpose

This GitHub repository stores only the reusable workflow and implementation assets:

- `SKILL.md` — operational source of truth.
- `assets/certificate_template.pptx` — current user-approved template.
- `scripts/fill_certificate.py` — conservative PPTX placeholder replacement.
- `scripts/inspect_template.py` — placeholder/layout inspection helper.
- `scripts/random_identity.py` — random pinyin name + layout-friendly student ID helper.
- `scripts/archive_record.py` — prepares a timestamp-named local three-file archive bundle before/alongside Google Drive upload.
- `tests/` — workflow tests.
- `docs/` — human-readable rules.

Specific school-generation records are no longer stored under GitHub `records/`. They belong in Google Drive.

## Google Drive archive

Every successful generation must be archived automatically to:

```text
大学PPT生成记录/<中文学校名>/
```

All three files from one generation use the same minute-precise timestamp stem:

```text
YYYY-MM-DD_HH-mm.md
YYYY-MM-DD_HH-mm.pptx
YYYY-MM-DD_HH-mm.png
```

Example:

```text
2026-08-27_01-11.md
2026-08-27_01-11.pptx
2026-08-27_01-11.png
```

Use the user's current local/session timezone. Student ID is no longer the normal record filename stem. If the same school already has a record for the exact same minute, append `_<student_id>` only to avoid overwriting.

The PNG must be rendered from the actual generated PPT, never generated by an image model.

The Markdown record stores the school/campus fields, coordinates, generated identity and student ID, generation timestamp/timezone, QA result, and the real Google Drive links returned for the matching PPT and PNG.

## Delivery order

In chat, always deliver the rendered PNG first, then the PPTX, then the school fields, with coordinates last. Google Drive archiving is automatic and must not require another user prompt.

## Local PPT generation

Python 3.10+ is sufficient; the core replacement script uses only the standard library.

```bash
python scripts/fill_certificate.py \
  --school-name "Xi'an Polytechnic University" \
  --output output.pptx
```

Automatic identities should prefer a short 7–8 digit student ID so the first certificate line remains on one line.

## Required visual QA

Before a generated PPT is delivered, render and inspect it. Confirm:

1. the first body line, including the student ID, remains a single line;
2. the second line onward reads as a normal continuous paragraph without replacement-created hard line breaks;
3. the body and bottom-right school names both use the same official English full name;
4. the bottom-right school name remains on one line;
5. `SAMPLE / NOT VALID` and `仅供演示，不具效力` remain visible.

If any check fails, regenerate and render again.

## Rule synchronization

When the user changes the workflow rules in an interactive conversation, update this repository immediately as part of the same change. `SKILL.md`, relevant English/Chinese docs, scripts, and tests should stay synchronized with the current workflow.

## Important

The bundled PPT is a demo template and must retain the visible `SAMPLE / NOT VALID` and `仅供演示，不具效力` markings.
